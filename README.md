# 보도자료 모니터

보도자료를 수집해 검색 가능한 웹 대시보드로 만드는 도구입니다.

대시보드 상단은 **정부기관 / 지자체 / 공공기관 / 연구소** 네 개 탭으로 나뉩니다.
탭마다 기관 체크박스·기간·검색어가 똑같이 동작하고, 목록은 기관명 / 제목 /
날짜로 나옵니다. 제목을 누르면 그 보도자료 원문이 새 탭에서 열립니다.

탭에 붙은 숫자는 **수집 대상 기관 수**입니다. 기사 건수는 날마다 출렁이지만
'몇 곳을 훑고 있는가'는 그 탭이 무엇을 덮는지 말해 줍니다. 그날 표시되는
건수는 목록 위 줄에 따로 나옵니다.

| 탭 | 기관 수 | 상태 |
|---|---|---|
| 정부기관 | 53곳 | korea.kr 통합 수집 |
| 지자체 | 8곳 | 서울 3곳(서울시·강동구·송파구), 경기 5곳(경기도·구리시·성남시·용인시·하남시) |
| 공공기관 | 6곳 | 게시판 7개 (서울주택도시개발공사는 보도·해명 2개) |
| 연구소 | 4곳 | 게시판 5개 (KB경영연구소는 연구·브랜드 2개) |

## 왜 이 구조인가

각 부처 홈페이지를 개별로 긁지 않습니다. **대한민국 정책브리핑(korea.kr)** 이
전 부처 보도자료를 한 곳에 모아 제공하고, 목록 단계에서 제목·부처·게시일·원문
링크가 모두 채워집니다. 어댑터 하나로 전 부처를 덮을 수 있고, 사이트 개편으로
깨질 지점도 한 곳으로 줄어듭니다.

## 설치

```bash
python -m pip install -r requirements.txt
```

## 사용

### 1. 정부부처 확인

```bash
python -m govpress depts
```

53개 기관을 구분(부·처 25 / 청 18 / 위원회 8 / 기타 2)별로 묶어
가나다순으로 보여 줍니다. 청은 어느 부 소속인지도 함께 표시합니다. `--dept`에는 정식 명칭,
줄임말(`국토부`, `금융위`, `식약처` 등), 코드(`A00006`) 중 아무거나 쓸 수 있습니다.

### 2. 수집

```bash
# 특정 부처만, 기간 지정
python -m govpress collect --dept 국토교통부 금융위원회 --from 26.08.01 --to 26.09.08

# 검색어로 좁히기
python -m govpress collect --dept 국토부 --keyword 부동산 --from 26.01.01 --to 26.09.08

# 전 부처, 최근 7일
python -m govpress collect --days 7
```

| 옵션 | 뜻 |
|---|---|
| `--dept 기관 [기관 ...]` | 수집할 정부부처. 여러 개 나열 가능 |
| `--from YY.MM.DD` / `--to YY.MM.DD` | 검색 기간. `2026-09-08` 형식도 됩니다 |
| `--days N` | 최근 N일 (기본 7, `--from/--to`가 있으면 무시) |
| `--keyword 단어` | korea.kr 검색어 |

부처·기간·검색어는 모두 **korea.kr이 서버에서 걸러 줍니다.** 다 받아 온 뒤
버리는 게 아니라 필요한 것만 요청하므로 훨씬 빠르고 사이트에도 부담이 적습니다.

### 3. 대시보드

```bash
python -m govpress dashboard --open

# 수집 + 대시보드 한 번에
python -m govpress run --dept 국토부 --days 30 --open
```

대시보드에서 다시 한 번 좁혀 볼 수 있습니다.

- **정부부처 체크박스** — 구분(부·처 / 청 / 위원회 / 기타)별로 묶고, 각 구분
  안은 가나다순. **수집 여부와 상관없이 전체 명단이 항상 나옵니다** — 그날
  발표가 없던 부처도 고를 수 있어야 하니까요. 건수 0인 곳은 흐리게 표시됩니다.
  기관별 건수 표시, 다중 선택, 전체선택/해제
- **검색 기간** — `YY.MM.DD ~ YY.MM.DD` 직접 입력 + 오늘/7일/30일/전체 버튼
- **검색어** — 제목·요약·기관에서 찾고 결과에서 하이라이트

제목을 누르면 해당 보도자료 원문이 새 탭에서 열립니다.

결과물:

- `articles.db` — SQLite. `(source, uid)` 기준으로 중복 저장되지 않으므로
  매일 돌려도 계속 쌓입니다.
- `dashboard.html` — 외부 리소스를 전혀 불러오지 않는 파일 하나.
  더블클릭으로 열리고, 공유 폴더에 그대로 올려도 동작합니다.

## 기관 이름 기준

기관명·구분·소속 관계는 **정부 조직도**를 기준으로 정리했습니다. 표기 자체는
korea.kr이 보도자료에 쓰는 이름을 따르고, 조직도 명칭이 다르거나 개편 전
이름으로 입력해도 찾아 줍니다.

| 입력 | 찾아가는 기관 |
|---|---|
| `특허청` | 지식재산처 |
| `통계청` | 국가데이터처 |
| `문화재청` | 국가유산청 |
| `산업통상자원부` | 산업통상부 |
| `여성가족부` | 성평등가족부 |
| `대통령비서실` | 청와대 (korea.kr 표기) |

여러 기관으로 나뉜 경우에는 어디로 갔는지 알려 줍니다.

```
$ python -m govpress collect --dept 기획재정부
오류: 기획재정부는 기획예산처와 재정경제부로 나뉘었습니다. 후속 기관 이름으로 지정하세요.
```

조직도에는 있지만 korea.kr이 보도자료를 제공하지 않는 기관(국가정보원,
고위공직자범죄수사처, 국가교육위원회, 대통령비서실 산하 조직 등)은 코드표에
없어 수집 대상이 아닙니다.

한국소비자원·금융감독원 같은 **공공기관도 korea.kr 브리핑룸에 발행 기관으로
나오지 않습니다.** 각 기관 홈페이지를 따로 읽어야 하므로 별도 수집기에서
다룹니다.

`govpress/agencies.py`의 `EXCLUDED`에 넣은 기관은 수집과 표시 양쪽에서
빠집니다. 전 부처를 훑을 때 기사가 딸려 들어와 다시 나타나는 걸 막기
위해서입니다. (현재: 국무조정실)

## 데이터 품질 기준

저장 전에 다음을 만족하지 못하는 항목은 버립니다.

- 제목, 원문 링크, 게시일, 고유 ID가 모두 있을 것
- 링크는 `pressReleaseView.do?newsId=...` 형태의 정규화된 permalink일 것

메뉴·배너 링크가 기사로 섞여 들어가지 않는지, 게시일이 비어 있지 않은지는
테스트로 고정해 두었습니다.

## 수집기를 새로 붙이려면

1. `govpress/<출처>.py`를 만들고 목록 HTML을 `list[Article]`로 바꾸는
   순수 함수(`parse_list`)를 둡니다. 네트워크는 별도 함수로 분리하세요 —
   그래야 저장해 둔 HTML fixture로 테스트할 수 있습니다.
2. 각 `Article`에 `category`(정부기관/지자체/공공기관/연구소)와
   `source`, 출처 안에서 고유한 `uid`를 채웁니다.
3. `storage.save()`로 넘기면 끝입니다. 중복 제거와 대시보드 탭은 자동입니다.

실제 목록 페이지를 저장한 fixture로 파서를 검증하는 방식은
`tests/fixtures/korea_list.html`과 `tests/test_korea_kr.py`를 참고하세요.

## 지자체 추가하기

```bash
python -m govpress locals                      # 수집 대상과 확인 대기 목록
python -m govpress collect-local               # 전체
python -m govpress collect-local --city 서울시  # 특정 지자체만
```

지자체는 통합 창구가 없어 사이트마다 어댑터가 하나씩 필요합니다.
`govpress/local_gov.py`의 `SITES`에 한 줄 추가하면 확장됩니다.

체크박스 순서는 **지역 안에서 광역이 먼저, 나머지는 가나다순**입니다.
광역시·도에는 `metro=True`를 붙이세요. 지역을 새로 늘릴 때도 그 지역의
광역 한 곳에만 붙이면 됩니다.

8곳을 붙여 보니 게시판이 네 종류였습니다.

| 파서 | 쓰는 곳 | 특징 |
|---|---|---|
| `parse_seoul` | 서울시 | 링크가 `javascript:fnTbbsView('...')` — 주소를 다시 조립 |
| `parse_standard_board` | 송파구, 구리시 | 행정표준 게시판. 칸 수가 사이트마다 달라 날짜 칸을 먼저 찾음 |
| `parse_card_board` | 하남시 | 표가 아니라 카드형 |
| `parse_seongnam` / `parse_yongin` / `parse_gyeonggi` / `parse_gangdong` | 각 1곳 | 고유 구조 |

### 구형 TLS 서버

성남시·용인시 서버는 오래된 TLS 설정만 지원해서, 요즘 파이썬으로 그냥
붙으면 `SSLV3_ALERT_HANDSHAKE_FAILURE`가 납니다. **차단이 아니라 악수
실패**입니다 — 브라우저는 하위 호환을 열어 두어 잘 열리므로 오해하기 쉽습니다.

악수가 되고 나면 이번엔 인증서에서 걸립니다(`CERTIFICATE_VERIFY_FAILED`).
국내 공공기관이 쓰는 루트 인증서는 윈도우 인증서 저장소에는 있지만 파이썬이
들고 다니는 `certifi` 목록에는 없기 때문입니다. 그래서 두 번째 단계에서
`truststore`로 **운영체제 저장소를 그대로 씁니다** — 브라우저가 보는 것과
같은 목록입니다.

수집기는 세 단계로 물러섭니다.

| 단계 | 하는 일 | 표시 |
|---|---|---|
| 1 | 기본 설정 | 없음 |
| 2 | 구형 TLS 허용 + OS 인증서 저장소 | `(구형 TLS)` |
| 3 | 인증서 검증 생략 | `(인증서 검증 생략)` |

실패한 뒤에만 다음 단계로 가고, 성공한 단계는 **그 호스트에 대해서만**
기억해 다음부터 바로 씁니다. 나머지 6곳은 1단계 그대로입니다. 낮추는 것은
우리 쪽이 받아들일 수준이고 대상은 공개된 보도자료 목록입니다 — 로그인도,
개인정보도 오가지 않습니다. 수집 로그에 어느 단계로 붙었는지 표시되니
3단계가 뜨면 그 사이트만 따로 살펴보면 됩니다.

### 페이지 넘기기

페이지 넘기는 방식도 제각각입니다 — `curPage`, `pageIndex`, `cp`, `page`,
`q_currPage`. 성남시는 페이지 이동이 POST뿐이라 대신 `cntPerPage`로 한 번에
많이 받습니다(`page_mode="size"`).

**구조를 확인하지 않은 지자체는 `SITES`에 넣지 않습니다.** `PENDING`에만
적어 둡니다. 짐작해서 쓴 파서는 조용히 메뉴 링크를 기사로 주워 담거나
빈 결과를 내는데, 그걸 알아채기가 어렵기 때문입니다.

## 공공기관·연구소 추가하기

```bash
python -m govpress publics                       # 공공기관 목록
python -m govpress collect-public                # 전체
python -m govpress collect-public --only 금융감독원

python -m govpress labs                          # 연구소 목록
python -m govpress collect-research
```

지자체와 구조가 같다. `public_org.py` / `research.py`의 `SITES`에 한 줄
추가하면 확장된다. 붙여 보니 지자체보다 훨씬 고르다 — 페이지 넘김이
`pageIndex`·`nPage`·`page`·`currPage` 네 가지뿐이었다.

### 한 기관에 게시판이 여럿일 때

서울주택도시개발공사는 보도자료와 해명자료가 따로 있고, KB경영연구소는
게시판이 셋이다. 이럴 때는 `Site`를 여러 개 두고 `board`로 구분한다.

```python
_site("서울주택도시개발공사", "부동산", "...m_139/list.do", "page", parse_sh,
      board="보도자료"),
_site("서울주택도시개발공사", "부동산", "...m_612/list.do", "page", parse_sh,
      board="해명자료"),
```

저장 열쇠(`source`)만 갈라지고, **화면에는 기관 이름 하나로 나오며 결과는
합쳐진다.** 체크박스도 하나고, 탭 숫자도 한 곳으로 센다.

### 같은 기관 안에서 내용이 겹치는 게시판

KB경영연구소는 시트에 게시판이 셋(연구보고서·브랜드보고서·지식비타민)
적혀 있었지만 **둘만 넣었습니다.** 연구보고서 목록이 지식비타민 글을
그대로 품고 있어서(27건 중 26건 확인), 셋 다 넣으면 같은 글이 목록에
두 번 나옵니다.

`(source, uid)` 중복 제거는 이걸 못 막습니다. 게시판이 다르면 글 번호도
다르고(`reportId` vs `vitaminId`), 제목까지 미묘하게 다른 경우가 있기
때문입니다 — 같은 글이 한쪽은 "두 가지 시선 - 오픈AI와 앤스로픽",
다른 쪽은 "두 가지 시선-오픈AI와 앤스로픽 이야기"였습니다.

**게시판을 여러 개 등록하기 전에 내용이 겹치는지 먼저 확인하세요.**
겹치면 넓은 쪽 하나만 넣습니다.

### 주소가 안 바뀌는 게시판

절반쯤은 페이지 버튼이 POST거나 AJAX라 주소창이 그대로다. 그래도 대개
**같은 파라미터를 주소에 실어 GET으로 요청하면 서버가 받아 준다** —
식품안전정보원, 한국부동산원, 서울주택도시개발공사가 그랬다. 목록 주소가
안 바뀐다고 수집이 안 되는 것은 아니므로, 페이지 버튼의 자바스크립트를
먼저 뜯어본다.

제목 링크도 마찬가지다. `javascript:` 나 `#none` 을 그대로 저장하면 나중에
열 수 없으므로, 함수 인자에서 글 번호를 뽑아 상세 주소를 새로 만든다.
